## 一、 前置知识
CS:APP中介绍的一下几个重要函数，在核心函数设计中应用广泛：
### 1. sigprocmask函数
**原型：**`int sigprocmask(int how, const sigset_t *set, sigset_t *oldset);`
**参数：**
- how：控制信号集的更改方式。
    - SIG_BLOCK：把 set 中的信号加入到当前的阻塞位图中。
    - SIG_UNBLOCK：从当前阻塞位图中移除 set 中的信号。
    - SIG_SETMASK：直接用 set 替换当前的整个阻塞位图。
- set：指向要操作的信号集的指针。
- oldset：如果不为 NULL，内核会将更改前的旧信号掩码写入其中（用于后续恢复现场）。
### 2.kill函数
**原型：**`int kill(pid_t pid, int sig);`
**参数：**
- pid：决定了信号的发送范围。
    - pid > 0：信号仅发送给进程 ID 等于 pid 的那一个特定子进程。
    - pid ==0：将信号发送给与发送进程属于同一进程组的所有进程。
    - pid ==-1：将信号发送给系统中所有进程。
    - pid < -1：信号将发送给进程组 ID 等于 |pid|（绝对值）的所有子进程。
- sig：要发送的信号（如 SIGINT、SIGTSTP、SIGCONT）。若为 0，则不发信号，仅用于探测目标进程或进程组是否存活。
### 3.sigsuspend函数
**原型：**`int sigsuspend(const sigset_t *mask);`
**参数：**
- mask：临时替换当前进程的信号掩码。
- 机制：
    - 临时用 mask（通常是空集）替换原有的锁，彻底放开对信号（如 SIGCHLD）的拦截。
    - 立刻让主线程进入休眠挂起状态，等待任意未屏蔽的信号将其唤醒。
### 4.waitpid函数
**原型：**`pid_t waitpid(pid_t pid, int *wstatus, int options);`
**参数：**
- pid：指定等待的目标。
    - pid > 0时，只等待进程ID等于pid的子进程，只要该子进程不结束，就会一直等待下去；
    - pid = -1时，等待任何一个子进程的退出，此时作用和wait相同；
    - pid = 0时，等待同一个进程组中的任何子进程；
    - pid < -1时，等待一个指定进程组中的任何子进程，这个进程组的ID等于pid的绝对值。
- wstatus：指向状态整数的指针。内核会写入子进程的退出状态，配合 WIFEXITED(正常退出)、WIFSIGNALED（异常退出）、WIFSTOPPED（暂停） 等宏进行解包分析。
- options：
    - WNOHANG：如果正在运行的子进程，立刻返回 0，绝不阻塞。
    - WUNTRACED：如果子进程被信号暂停，也立刻返回其 PID。



## 二、 核心函数设计思路
本实验的核心任务是补全 `tsh.c` 中的关键控制函数。以下是核心函数的具体实现思路：

### 1. eval函数

`eval` 是整个 Shell 的入口，负责解析用户输入的命令行并派生子进程。它的核心难点在于**如何安全地协调父子进程的账本同步**。

 **实现思路**：
  1. 首先调用 `parseline` 解析命令行，切分出参数数组 `argv`，并判断该任务是前台（FG）还是后台（BG）。
  2. 利用 `builtin_cmd` 识别是否为内置命令（如 `quit`, `jobs`, `bg`, `fg`），如果是，则直接在主进程中执行并返回。
  3. 如果是非内置命令，父进程在 `fork()` 之前，必须先通过 `sigprocmask` 阻塞 `SIGCHLD` 信号。这是为了防止子进程运行过快，在父进程还没来得及将其加入账本（`addjob`）之前就触发了收尸 Handler，导致账本逻辑彻底错位。
  4. `fork()` 分流后：
     * **子进程**：立即解除对 `SIGCHLD` 的阻塞，恢复干净的信号状态，并调用 `setpgid(0, 0)` 将自己放入独立的进程组（防止键盘信号误杀父进程），最后执行 `execve` 加载程序。
     * **父进程**：首先调用 `addjob` 把新出生的子进程记录到全局账本中。在 `addjob` 之后，我没有盲目地直接解开全部信号锁。因为如果此时彻底解锁，在前台主线程还没在 `waitfg` 挂起之前，一旦子进程暴毙，排队的 `SIGCHLD` 会立刻触发后台收尸，导致主线程随后的 `waitfg` 永远错过这个唯一的唤醒闹钟。因此，我在这里将锁降级为 `mask_one`（继续挡住 `SIGCHLD`），护送主线程安全进入 `waitfg`，直到 `waitfg` 结束后，才在临出门前彻底解开所有的锁。


```c
/*
 * eval - Evaluate the command line that the user has just typed in
 *
 * If the user has requested a built-in command (quit, jobs, bg or fg)
 * then execute it immediately. Otherwise, fork a child process and
 * run the job in the context of the child. If the job is running in
 * the foreground, wait for it to terminate and then return.  Note:
 * each child process must have a unique process group ID so that our
 * background children don't receive SIGINT (SIGTSTP) from the kernel
 * when we type ctrl-c (ctrl-z) at the keyboard.
 */
void eval(char *cmdline)
{
    char *argv[MAXARGS]; // 参数列表
    pid_t pid;           // 进程PID
    int state;           // 是否在后台运行，命令结尾是否有&

    sigset_t mask_all, mask_one, prev_one;

    // 1.先进行解析命令，把"ls -l"变成argv[0]="ls"，argv[1]="-l"
    if (parseline(cmdline, argv))
        state = BG;
    else
        state = FG;

    // 空命令行:直接返回
    if (argv[0] == NULL)
        return;

    // 2.判断前后台运行,如果是内部命令直接在builtin_cmd中执行并结束
    if (!builtin_cmd(argv))
    {
        // 3.不是内部命令，先fork一个子进程然后在子进程中加载程序
        // 先初始化信号集
        sigfillset(&mask_all);
        sigemptyset(&mask_one);
        sigaddset(&mask_one, SIGCHLD);

        // 阻塞SIGCHLD信号，防止子进程fork出来还没addjob就暴毙
        sigprocmask(SIG_BLOCK, &mask_one, &prev_one);

        if ((pid = fork()) == 0)
        {
            // fork出来子进程时恢复原来的阻塞，防止子进程一直阻塞
            sigprocmask(SIG_SETMASK, &prev_one, NULL);
            // 自己成立一个进程组(否则向整个进程组发信号)，保证ctrl+c只发给当前进程
            setpgid(0, 0);
            if (execve(argv[0], argv, environ) < 0)
            {

                // 如果execve返回了，说明执行失败
                printf("%s: Command not found.\n", argv[0]);
                exit(0); // 子进程必须退出程序，否则子进程返回eval变成另一个shell
            }
        }
        // 在添加工作时阻塞全部信号
        sigprocmask(SIG_BLOCK, &mask_all, NULL);
        addjob(jobs, pid, state, cmdline);         // 把出生的工作放在工作本里
        sigprocmask(SIG_SETMASK, &mask_one, NULL); // 添加完工作后阻塞信号，但是不能解锁CHLD
        // 这里不能解锁CHLD是因为如果此时调度了子进程且运行完成，直接就去收尸了，waitfg不能收到子进程状态变化了，就会一直挂起

        // 判断前后台运行
        if (state == FG)
        { // 如果是前台，等待子进程结束收尸
            waitfg(pid);
        }
        else
        { // 如果是后台，只打印一行提示
            printf("[%d] (%d) %s", pid2jid(pid), pid, cmdline);
        }
        sigprocmask(SIG_SETMASK, &prev_one, NULL);
    }

    return;
}
```

### 2. builtin_cmd函数

`builtin_cmd` 负责判断并处理 Shell 内部自带的内置命令。如果属于内置命令，则直接在本进程中同步执行完毕，不再创建新的子进程。

**实现思路**：
  1. 通过 `strcmp` 逐一比对用户输入的第一个参数 `argv[0]`。
  2. **`quit` 命令**：直接调用 `exit(0)` 退出当前整个 Shell 进程。
  3. **`jobs` 命令**：直接调用实验提供的 `listjobs(jobs)` 函数，将当前账本中所有`job`打印出来
  4. **`bg` 和 `fg` 命令**：由于涉及前后台状态的切换以及信号的重新唤醒，它们属于复杂的内置命令，因此在这里统一调用 `do_bgfg(argv)` 函数去进行处理。
  5. 如果以上都不是，说明是外部可执行程序命令，函数返回 `0`，交由 `eval` 正常去派生子进程。

**细节**：
  在处理 `bg` 和 `fg` 时，因为命令后面还会跟着 `%jid` 或 `pid` 参数（如 `fg %1`），所以必须把整个 `argv` 参数数组原封不动地传递给 `do_bgfg`，方便后续进行参数解析与合法性校验。

```c
/*
 * builtin_cmd - If the user has typed a built-in command then execute
 *    it immediately.
 */
int builtin_cmd(char **argv)
{
    if (strcmp(argv[0], "quit") == 0)
        exit(0);
    else if (strcmp(argv[0], "jobs") == 0)
        listjobs(jobs);
    else if (strcmp(argv[0], "bg") == 0 || strcmp(argv[0], "fg") == 0)
        do_bgfg(argv);
    else
        return 0; // 不是内置命令直接返回
    return 1;
}
```

### 3. do_bgfg函数

`do_bgfg` 负责处理 `bg <job>` 和 `fg <job>` 内置命令。它的职责是把一个被键盘信号挂起的任务重新唤醒，并决定是让它在后台运行，还是在前台运行。

**实现思路**：
  1. **检验合法性**：首先检查 `argv[1]` 是否为空。如果用户只输入了 `bg` 或 `fg` 却没有带后续参数，必须立刻打印报错提示。
  2. **`pid`or`jid`判断**：
     * 如果参数以 `%` 开头，说明输入的是 **JID**。跳过百分号后，用 `atoi` 转换为数字，并调用 `getjobjid` 去全局账本中查找。
     * 如果参数开头是数字（利用 `isdigit` 判断），说明输入的是 **PID**。直接用 `atoi` 转换后，调用 `getjobpid` 去查找。
     * 如果都不满足（例如输入了 `bg abc`），直接报错。
  3. **修改状态并发信号**：
     * **`bg` 命令**：先将账本中的任务状态修改为 `BG`，然后先打印后台启动提示，最后调用 `kill(-pid, SIGCONT)` 给整个子进程组发送连续信号，让挂起的进程唤醒。
     * **`fg` 命令**：将账本中的任务状态修改为 `FG`，调用 `kill(-pid, SIGCONT)` 唤醒进程。由于该任务来到了前台，主线程必须在原地调用 `waitfg(pid)` ，直到它运行完或被重新挂起。

* **Debug 踩坑记录**：
  * **踩坑 1：变量作用域遮蔽导致的数据覆盖**。在最初的版本中，我在 `else if (isdigit(...))` 分支里手滑写成了 `int pid = atoi(argv[1]);`。这相当于在局部作用域内创建了一个同名的新变量，把函数开头的 `pid` 隐藏了。导致走出分支后，最后执行 `pid = job->pid` 时拿到了未初始化的垃圾值，引发了诡异的行为。发现后及时去掉了分支内的 `int` 声明，确保了全局变量的一致性。
  * **踩坑 2：格式比对的细节**。官方测试脚本（如 `trace14`）对报错文本有极为死板的格式匹配。如果找不到输入的 JID，报错格式必须是 `%jid: No such job`；如果找不到 PID，格式则是 `(pid): No such process`。调换了这两个格式导致 `diff` 报错，经过精细调整后最终达成了完美对齐。

```c
/*
 * do_bgfg - Execute the builtin bg and fg commands
 */
void do_bgfg(char **argv)
{
    struct job_t *job = NULL;
    int jid;
    int pid;

    // 检验：检查bg/fg有没有带参数
    if (argv[1] == NULL)
    {
        printf("%s command requires PID or %%jobid argument\n", argv[0]);
        return;
    }
    // 解析:是pid还是jid
    if (argv[1][0] == '%')
    {
        // 说明是JID，跳过%，并把后面的字符串转换为数字
        jid = atoi(&argv[1][1]);
        job = getjobjid(jobs, jid);
        if (job == NULL)
        {
            printf("%%%d: No such job\n", jid); 
            return;
        }
    }
    else if (isdigit(argv[1][0]))
    {
        // 说明是PID，直接把字符串转换为数字
        pid = atoi(argv[1]);
        job = getjobpid(jobs, pid);
        if (job == NULL)
        {
            printf("(%d): No such process\n", pid);
            return;
        }
    }
    else
    {
        // 输入了乱七八糟的非数字参数 (如 bg abc)
        printf("%s: argument must be a PID or %%jobid\n", argv[0]);
        return;
    }
    // 核心任务：修改状态并发信号重新唤醒
    pid = job->pid;
    if (strcmp(argv[0], "bg") == 0)
    { // 如果是后台指令
        // 1.修改状态
        job->state = BG;
        // 2.打印提示
        printf("[%d] (%d) %s", job->jid, job->pid, job->cmdline);
        // 3.发信号
        kill(-pid, SIGCONT);
        
    }
    else
    { // 如果是前台指令
        // 1.修改状态
        job->state = FG;
        // 2.发信号
        kill(-pid, SIGCONT);
        // 3.等待前台完成
        waitfg(pid);
    }
    return;
}
```

### 4. sigchld_handler函数

当子进程终止、停止或恢复时（状态发生变化），内核会向父进程发送 `SIGCHLD` 信号。`sigchld_handler` 负责回收僵尸进程并维护全局账本的状态。

**实现思路**：
  1. **信号安全与 `errno` 保护**：作为信号处理函数，它随时可能打断主线程的控制流。如果它内部的 `waitpid` 报错，会无情覆盖掉主线程刚刚建立的全局 `errno` 现场。因此，我在函数一进门就使用 `int olderrno = errno;` 将原始现场快照保存，在临出门前再恢复，彻底消除了这个副作用。
  2. **循环回收（非阻塞）**：由于 Linux 信号是不排队的，如果多个子进程同时暴毙，内核可能只向父进程发射一个 `SIGCHLD`。为了防止僵尸进程漏网，我使用了 `while` 循环，配合 **`WNOHANG`**（非阻塞，没死掉的进程就立刻跳过）和 **`WUNTRACED`**（同时追踪被挂起的进程）标志位，做到只要有变动就一口气全部捕捉。
  3. **三种情况处理**：
     * **正常退出（`WIFEXITED`）**：说明子进程自己跑完了，直接调用 `deletejob` 从全局账本里删除。
     * **信号终止（`WIFSIGNALED`）**：说明子进程是被外部信号（如用户按了 `Ctrl+C` 发送的 `SIGINT`）掐死的。此时需要用 `WTERMSIG` 取出掐死它的信号编号，**严格按照`reftsh`的文本格式打印终止通知**，然后从账本中删除。
     * **暂时挂起（`WIFSTOPPED`）**：说明子进程是被挂起信号（如用户按了 `Ctrl+Z` 发送的 `SIGTSTP`）挂起了。它并没有死，因此绝对不能删账本，而是用 `WSTOPSIG` 取出信号编号，**打印挂起通知**，并将**账本中的状态修改为 `ST`**。

```c
/*
 * sigchld_handler - The kernel sends a SIGCHLD to the shell whenever
 *     a child job terminates (becomes a zombie), or stops because it
 *     received a SIGSTOP or SIGTSTP signal. The handler reaps all
 *     available zombie children, but doesn't wait for any other
 *     currently running children to terminate.
 */
void sigchld_handler(int sig)
{
    // 保存原始errno，防止影响主线程
    int olderrno = errno;
    pid_t pid;
    int status;

    while ((pid = waitpid(-1, &status, WNOHANG | WUNTRACED)) > 0)
    {
        // 情况一：子进程正常退出
        if (WIFEXITED(status))
        {
            deletejob(jobs, pid); // 直接删除工作集
        }
        // 情况二：被外部信号掐死
        else if (WIFSIGNALED(status))
        {
            int sig_num = WTERMSIG(status); // 获取掐死信号
            // 严格按照官方要求的格式打印异常终止通知
            printf("Job [%d] (%d) terminated by signal %d\n", pid2jid(pid), pid, sig_num);
            deletejob(jobs, pid); // 从工作集中删除
        }
        // 情况三：被暂时挂起
        else if (WIFSTOPPED(status))
        {
            int sig_num = WSTOPSIG(status); // 获取挂起信号
            // 严格按照官方要求的格式打印挂起通知
            printf("Job [%d] (%d) stopped by signal %d\n", pid2jid(pid), pid, sig_num);
            // 它还没有死，不能直接删除，修改它的状态即可
            struct job_t *job = getjobpid(jobs, pid);
            if (job)
            {
                job->state = ST;
            }
        }
    }
    errno = olderrno;
    return;
}
```

### 5. sigint_handler函数

当用户在键盘上按下 `Ctrl + C` 时，内核会向 Shell 主进程发送 `SIGINT` 信号。该函数作为处理函数，负责将中断信号精准转发给前台作业。

**实现思路**：
  1. **信息保护**：由于信号处理函数的异步触发特性，一进门首先保存全局 `errno` 现场（`int olderrno = errno;`）。
  2. **获取前台作业PID**：调用 `fgpid(jobs)` 路由到当前正在前台运行的作业 PID。
  3. **发送信号**：如果发现当前有前台作业（`pid != 0`），调用 `kill(-pid, SIGINT)` 发送信号。
  4. **负号 `-pid` 的关键作用**：这里使用负号是整个 Shell 能够合规运行的核心细节。它代表向**该 PID 所在的整个前台进程组**群发信号。这样不仅能杀掉前台子进程，还能连带将其派生出的所有孙子进程一并杀死，防止产生不受控制的孤儿后台进程。


```c
/*
 * sigint_handler - The kernel sends a SIGINT to the shell whenver the
 *    user types ctrl-c at the keyboard.  Catch it and send it along
 *    to the foreground job.
 */
void sigint_handler(int sig)
{
    int olderrno = errno; // 保护errno

    pid_t pid = fgpid(jobs);

    if (pid != 0)
    {
        // 向整个子进程组发信号
        kill(-pid, SIGINT);
    }

    errno = olderrno;
    return;
}
```

### 6. sigtstp_handler函数

当用户在键盘上按下 `Ctrl + Z` 时，内核会向 Shell 主进程发送 `SIGTSTP` 信号。该函数负责拦截该信号，并将挂起动作接力转发给前台作业。

**实现思路**：
  1. **信息保护**：同样在入口处对 `errno` 进行异步信号安全保护（`int olderrno = errno;`），防止对主线程造成干扰。
  2. **获取前台作业PID**:调用 `fgpid(jobs)` 查询账本，获取当前占领终端的前台进程 PID。
  3. **发送信号**:如果前台有任务在跑（`pid != 0`），调用 `kill(-pid, SIGTSTP)`，同样利用**负号**向整个前台进程组发送停止信号，将前台所有关联进程挂起。


```c
/*
 * sigtstp_handler - The kernel sends a SIGTSTP to the shell whenever
 *     the user types ctrl-z at the keyboard. Catch it and suspend the
 *     foreground job by sending it a SIGTSTP.
 */
void sigtstp_handler(int sig)
{
    int olderrno = errno;

    pid_t pid = fgpid(jobs);

    if (pid != 0)
    {
        kill(-pid, SIGTSTP);
    }

    errno = olderrno;
    return;
}
```

    E -->|fflush 清空缓存区 / 反复调用| E
    E --> P[parseline 解析命令行]
    
    %% 命令分流
    P -->|quit, bg, fg, jobs 内置命令| B[builtin_cmd]
    P -->|外部命令| LOCK[sigprocmask 阻塞 SIGCHLD 防止竞争]
    LOCK --> F[fork 派生双端控制流]
    
    %% builtin_cmd 分支
    B -->|quit| B1[exit 0]
    B -->|jobs| B2[listjobs --> printf]
    B -->|bg / fg| D[do_bgfg]
    
    %% do_bgfg 内部解析
    D --> D1[ atoi 参数解析]
    D1 -->|'%' 开头| D2[对象为 JID ]
    D1 -->|数字开头| D3[对象为 PID]
    D2 & D3 --> D4[获取 job 本体]
    
    D4 -->|命令为 bg| BG1[修改状态为 BG]
    D4 -->|命令为 fg| FG1[修改状态为 FG]
    
    %% fork 父进程分支
    F -->|父进程空间| PARENT[addjob 登记全局账本]
    PARENT --> P_CH{判断前后台模式}
    P_CH -->|前台 FG| FG2[waitfg 挂起 ]
    P_CH -->|后台 BG| BG2[打印后台运行提示]
    
    %% fork 子进程分支
    F -->|子进程空间| CHILD[解除 SIGCHLD 信号阻塞]
    CHILD --> CH_PG[setpgid 0, 0 放入独立进程组]
    CH_PG --> EX[execve 加载目标文件]

    %% 右侧异步信号处理例程
    subgraph 信号处理例程函数
        %% SIGCHLD
        H1[sigchld_handler <-- SIGCHLD 触发] --> W[while waitpid 非阻塞循环]
        W -->|WIFSTOPPED 暂停信号| W1[printf 提示 --> WSTOPSIG --> 账本改 ST]
        W -->|WIFEXITED 正常退出| W2[printf 提示 --> WEXITSTATUS --> deletejobs]
        W -->|WIFSIGNALED 强杀退出| W3[printf 提示 --> WTERMSIG --> deletejobs]
        
        %% SIGINT
        H2[sigint_handler <-- SIGINT 触发] --> I1[fgpid 获取前台 --> kill -pid, SIGINT 组转发]
        
        %% SIGTSTP
        H3[sigtstp_handler <-- SIGTSTP 触发] --> T1[fgpid 获取前台 --> kill -pid, SIGTSTP 组转发]
        

    end

    %% 给核心函数上色
    class M,E,B,D,FG2,FG1,P,F,LOCK mainFunc;
    class H1,H2,H3,H4 handlerFunc;
    class B1,B2,W1,W2,W3,I1,T1,Q1,BG1,EX,BG2,PARENT,CHILD,CH_PG leafNode;

## 四、实验总结


本次实验通过补全部分函数构建了一个较为简单点的外壳，这不仅是一次代码编写的练习，更是一场对抗多进程高并发竞争的实战。在编写函数与反复 Debug 的过程中，我深刻体会到了线性串行思维在面对操作系统异常控制流时的局限性，并获得了以下几点核心收获与反思：

### 1. 对异常控制流的认识加深
在 `fork()`、`execve()` 时，它们只是抽象的函数。但通过亲自编写 `eval`、`waitfg` 和四大信号处理 Handler，这些概念彻底活了过来：
* 深刻理解了为什么父进程在 `fork` 前必须提前加锁（`sigprocmask`）来防止子进程立即`fork`后立即死掉
* 搞懂了 `setpgid(0, 0)` 建立独立进程组的底层逻辑，从而避免键盘信号（`Ctrl+C`/`Ctrl+Z`）杀死整个进程组的进程。

### 2. 对信号的认识加深
信号处理函数不是普通的被动调用，而是一个随时可能打断主线程的隐式并发流。结合 CS:APP ，我理清了以下两点物理特性：
* **异步信号安全性**：Handler 会强行打断主线程的执行现场。如果在 Handler 入口处不对全局 `errno` 进行保护，Handler 内部隐式的系统调用报错就会无情冲刷主线程的上下文现场，引发难以排查的侧面副作用。
* **信号的不排队性**：Linux 内核中同种类型的信号只能通过一个位来标记挂起状态，因此它是不排队的。后方的回收例程按照 CS:APP 的提供的方法，依靠带有 `WNOHANG` 标志的 `while` 循环对死掉的子进程全部回收，才能确保在多个子进程同时触发 `SIGCHLD` 时不发生信号丢失，彻底消除僵尸进程。

### 3. 结语
一个合格的 Shell 绝对不是“能跑通 `ls` 就行”的玩具，而是一个必须时刻保持警惕、在后方默默处理各种子进程暴毙和自杀突发情况。
通过本次 Lab ，我对CS:APP异常控制这一章的内容有了更深的理解。
